# SQL 마이그레이션

2026-11-15 부터 git 으로 관리한다. 그 전 파일(`sql/01~58_*.sql`)은 버전관리 밖에 있었고 삭제 예정이다(`.gitignore` 로 계속 제외).

## 폴더

| 폴더 | 스키마 | 대상 |
|---|---|---|
| `stock/` | `stock` | 비밀상회(private 고객, 트레이딩) + 시장 데이터 원본(배치가 씀) |
| `yangbong/` | `yangbong` | 양봉상회(대중용). 회원·서비스 데이터 + 시장 데이터 읽기 전용 뷰 |

어떤 테이블이 어느 쪽인지는 `기획안_양봉상회-개혁.md` 16장의 분류표를 따른다.

## 규칙

- **번호**: 폴더마다 따로 `000_`, `001_` … 세 자리로 매긴다. 번호는 다시 쓰지 않는다.
- **비밀값 금지**: 비밀번호·API 키·토큰을 파일에 쓰지 않는다. `'<비밀번호>'` 같은 자리표시로 두고 실행할 때만 바꾸며, 바꾼 파일은 커밋하지 않는다. `master_infos` 의 값(연동 키)은 데이터로 덤프하지 않는다.
- **머리말**: 파일 맨 위에 목적, 적용 순서(SQL → API → 워커 재시작 → 프런트 등), 확인 쿼리, 되돌리기를 적는다.
- **수동 적용**: DB 반영은 사람이 관리자 계정으로 한다. 적용했으면 커밋 메시지나 PR 에 "적용함"을 남긴다.
- **구조를 같이 바꿔야 하는 테이블**: `yangbong` 의 회원·인증·메뉴·설정 테이블은 `stock` 과 같은 구조로 만들었다(`CREATE TABLE … LIKE`). `stock` 쪽 구조를 바꾸면 `yangbong/` 에도 같은 변경 파일을 넣는다. 시장 데이터 원본에 컬럼을 추가하면 `yangbong/003_market_views.sql` 의 해당 뷰를 다시 실행해야 새 컬럼이 보인다.

## 기준점

`stock/000_baseline_schema_YYYYMMDD.sql`(구조만)과 `stock/001_baseline_config_YYYYMMDD.sql`(화면·운영 설정 데이터, `master_infos`·회원·매매 데이터 제외)은 예전 01~58 을 대신하는 현재 상태 스냅샷이다. 새 변경은 `stock/002_` 부터 이어간다.
