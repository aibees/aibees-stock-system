# 양봉상회 화면 ↔ 파이썬 서버 ↔ DB 연결 전수조사 (2026-11-15)

대상: `yangbong-store-vue` 의 모든 화면이 부르는 API → `py-naver-stock-theme` 라우터 → 읽고 쓰는 테이블·외부 API → `yangbong` 스키마(`py-project/sql/yangbong/001~005`)에 있는지.
방법: 프런트 `aibeesApi` 호출 전수 추출, 라우터 데코레이터 추출, 라우터에서 import 를 따라가며 SQL 문자열·ORM 모델의 테이블 수집. 코드는 고치지 않았다.

## 2. 서버(파이썬) 쪽에서 할 일

1. **(A, 지금)** 배치·메뉴 관리 API 에 `@require_admin` 붙이기. 양봉상회 서버에는 `batch_bp` 자체를 등록하지 않기.
2. **(B)** KIS 의존을 걷어 내기. 선택지:
   - 차트는 DB 뷰 `stock_ohlcv_daily` 로 읽기(실시간 대신 전일까지). KisEngine 은 필요할 때만 만들기(import 시점 생성 제거).
   - 재무·뉴스는 배치가 미리 받아 테이블에 두고 API 는 읽기만(양봉상회 서버는 KIS 키를 아예 모르게).
   - 또는 양봉상회 서버에 조회 전용 KIS 키를 환경변수로 따로 주기(회원 테이블에 키를 두지 않는 조건).
3. **양봉상회 서버 구성**: 같은 코드 + `DB_URL`(yangbong_api) + 다른 `JWT_SECRET_KEY`, 공개용 블루프린트만 등록 — stocks·charts·indicators·anthropic(조회·제한된 생성)·user-options·access-logs(POST)·notices·oauth·master(menus/my·menus GET). 등록하지 않을 것: batch, strategy, users(account_trade), profit, auto-trade, manual-buy/sell, common-codes 쓰기.
4. **(D)** AI 분석 생성 제한: 관리자만 생성하거나, 하루 생성 횟수 한도.
5. **새 API**: 테마(양봉상회 전용), 관심종목(`user_interest_*` 테이블은 이미 있음, 라우터 `router_favorite.py` 는 빈 파일·미등록), 필요하면 트레이닝 진행·나만의 설정 동기화.
6. 서비스별로 달라야 할 상수: 가입 메일 제목, 약관 버전, 기본 가입 권한(비밀상회는 가입 즉시 STOCK_USER).

## 7. 조치 (2026-11-16) — 0번의 A·B·C·D

코드·SQL 만 고쳤다. DB 적용·배포·커밋은 하지 않았다. 검증은 로컬에서 Flask test client 로 했다(운영 DB 읽기만, KIS·Anthropic 호출은 가로채서 0회).

### A. 관리 API 인증 — 조사 중 더 나온 것까지

| 구멍 | 조치 |
|---|---|
| 비밀상회 API 배치 정의·실행·로그(`/master/batch-jobs` 5개, `/batch/execute`, `/batch-logs`) | `@require_admin` |
| 메뉴 추가·수정·켜고 끄기, 관리용 조회(`/menus/head·sub`) | `@require_admin`. `GET /master/menus` 는 공개 유지(비로그인 라우트 생성용) |
| **배치 서버(py-stock-batch)도 인증이 전혀 없었다.** 웹 nginx 가 `/api/v1/jobs`·`/api/v1/notify` 를 그대로 넘겨서 누구나 배치 실행(`/jobs/once`)·재적재·**전체 푸시 발송**(`/notify/test-send`) 가능 | 새 `app/flask_app/utils/auth.py` — 비밀상회 API 가 발급한 토큰을 같은 키로 검증해 ADMIN 만. 서버 안 curl 용으로 `X-Batch-Key` 헤더(선택) |

검증: 토큰 없음 401 · 옛 고정 문자열로 위조한 관리자 토큰 401 · 만료 401 · 일반 회원 403 · 관리자 200 (API 18건, 배치 서버 15건).

### B. 양봉상회 서버 기동

- import 시점 KIS 키 조회 3곳 제거: `StockService`(매수추천·차트 라우터), `router_strategy`, **`app/main.py` 가 맨 위에서 import 하던 `app/test/mcp_test_1.py`**(검증 중 발견 — gunicorn 도 이 경로를 탄다).
- `APP_SERVICE=yangbong`(새 `app/utils/service.py`): 공개 블루프린트 9개만 등록·import(배치·전략·매매·공통코드 관리 없음), `KIS_ENABLED` 기본 false.
- KIS 를 안 쓰면 차트·추천 기록은 DB 일봉(`stock_ohlcv_daily`, 전 거래일까지)으로 그린다 — 새 `services/stocks/dailyBarSource.py`. 주봉 = 그 주 첫 거래일, 월봉 = 마지막 거래일(KIS 와 같은 날짜). KIS 를 쓰는 서버도 키가 없으면 DB 로 그린다.
- 재무 → 404 "재무 지표는 아직 제공하지 않습니다." / 뉴스 → 새로 만들지 않고 저장분만(출처 결정 전까지).
- 띄우는 설정: `py-naver-stock-theme/docker-compose.yangbong.yml`(컨테이너 `yangbong-web-flask-app`, 172.21.1.8) + `.env.yangbong`(예시 파일 있음).
- 검증(양봉상회 모드): import 시점 KIS 조회 0회, 배치·전략·공통코드 경로 404, 일봉 200봉·주봉·월봉·추천 기록·종목 검색 200.

### D. AI 분석 생성 한도

- 생성 기록 표 `stock_ai_gen_log`(`sql/stock/002`, `sql/yangbong/007`). AI 를 부르기 **전에** 기록하고 실패하면 지운다.
- 사용자별 하루 `GEN_PER_USER_DAY`(관리자 제외)·서버 전체 하루 `GEN_TOTAL_DAY`. 공통코드 `stock/setting/ai` → 환경변수 → 기본값(양봉상회 5·100, 비밀상회 30·300).
- 넘으면 429 + 문구, 화면(두 앱 StockInfo)은 그 문구를 alert. 뉴스(조회 시 자동 생성)는 넘으면 지난 내용을 보여 준다.
- 표가 없으면 관리자 외 생성 차단(fail closed) → **SQL 을 API 배포보다 먼저** 적용.

### 배포 순서

1. SQL: `stock/002_stock_ai_gen_log.sql`(비밀상회). 양봉상회는 001~005 다음 006·007.
2. 서버에 `.env` 만들기(각 `.env.example` 참고):
   - `py-naver-stock-theme/.env` → `JWT_SECRET_KEY`
   - `py-stock-batch/.env` → 같은 `JWT_SECRET_KEY` + (선택) `BATCH_ADMIN_KEY`
   - 없으면 compose 가 기동을 거부한다.
   - 로컬 두 파일은 이번에 무작위 값으로 만들어 두었다(gitignored).
3. 비밀상회 API·배치 서버 재배포. 키가 바뀌므로 발급된 accessToken(30분)은 무효가 된다. 앱은 refreshToken 으로 조용히 다시 받는다.
4. 비밀상회 웹 재배포(한도 문구 alert, 선택).
5. 양봉상회 API: `.env.yangbong`(DB 계정·**다른** JWT 키) → `docker compose -f py-naver-stock-theme/docker-compose.yangbong.yml up -d`. 웹의 `/api` 를 이 컨테이너로 돌리는 nginx 변경은 도메인 결정 뒤.

### 남은 것 (이번에 안 고침)

- **yangbong 001 ↔ 002 계정 이름 불일치**: 001 의 `CREATE USER` 는 `'yangbong'@'%'`, 002 의 GRANT 21줄은 `'yangbong_api'@'%'`. MySQL 5.7 기본 sql_mode(NO_AUTO_CREATE_USER)에서는 002 GRANT 가 실패한다. 007 은 `'yangbong'` 으로 썼다.
- 비로그인(BASIC 단계) 매수추천은 `trade_buy_target_basic` 이 비어 있어 0건이다(테이블 행 0, 11/12 종합순위는 1건).
- 서버 안에서 curl 로 배치를 돌리던 방식(ShapeTrainJob 등 docstring 의 `POST /api/v1/jobs/once/…`)은 이제 `X-Batch-Key` 헤더가 필요하다.
- 코드에 박힌 기본 비밀값: `shared/stock_shared/db/database.py` 기본 DB_URL, `app/mcp_oauth.py` 기본 MCP_CLIENT_SECRET. 운영에서 환경변수로 덮고 있는지 확인 필요.
- 배치 서버 `/jobs/status` 는 스케줄러가 안 켜진 프로세스에서 400(`next_run_time` 없음) — 원래 동작, 인증과 무관.
