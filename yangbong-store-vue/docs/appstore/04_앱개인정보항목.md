# 양봉상회 App Store 개인정보 항목 (App Privacy)

기준: 2026-11-20 코드(iOS 1.1.4, 번들 ID `com.chagoklabs.yangbongstore`). App Store Connect > 앱 > **앱 개인정보 보호**에 그대로 입력하는 용도.

## 1. 앱에 들어간 SDK

| SDK | 패키지 | 하는 일 | 데이터 수집 |
|---|---|---|---|
| Capacitor 8.5 (Core, iOS) | `@capacitor/core`, `@capacitor/ios` | 웹 화면을 앱으로 감싸는 런타임 | 없음 |
| Capacitor Splash Screen | `@capacitor/splash-screen` | 시작 화면 | 없음 |
| Google Mobile Ads (AdMob) | `@capacitor-community/admob` 8.2 | 하단 배너, 보상형 광고, ATT 추적 동의, UMP 동의 | 있음 (광고 식별자, 광고 데이터, 대략적 위치, 진단) |
| Firebase Cloud Messaging | `@capacitor-firebase/messaging` 8.4 | 푸시 알림 토큰 발급·수신 | 있음 (FCM 토큰, Firebase 설치 ID) |
| Sign in with Apple | 앱 안 플러그인 `AppleSignInPlugin.swift` (Apple AuthenticationServices) | Apple 로그인, 계정 삭제 때 재인증 | Apple 회원 식별값, 이메일, 이름 → 운영자 서버 |

- **없는 것**: Firebase Analytics, Crashlytics, 다른 분석 SDK, 결제 SDK, 위치 권한, 카메라·사진·연락처 접근.
- `firebase` npm 패키지는 의존성에 있지만 앱 화면 코드에서 쓰지 않음(푸시는 네이티브 플러그인만 사용).
- 로그인: **Apple**(iOS 앱만, 네이티브), **네이버**(웹 OAuth 리다이렉트), **이메일 가입**. 구글 로그인은 iOS 앱에서는 숨김(웹 전용).
- 관심 종목은 기기 저장소에만 저장 → 수집 아님.

| 동의 기록 | `user_consent` | 약관·방침 버전 |

## 3. App Store Connect 입력값

**"귀하 또는 타사 파트너가 이 앱에서 데이터를 수집합니까?"** → **예**

| Apple 데이터 유형 | 수집 주체 | 용도 (Apple 선택지) | 사용자에 연결 | 추적에 사용 |
|---|---|---|---|---|
| 연락처 정보 > **이름** | 운영자 서버 | 앱 기능 | 예 | 아니요 |
| 연락처 정보 > **이메일 주소** | 운영자 서버 | 앱 기능 | 예 | 아니요 |
| 식별자 > **사용자 ID** | 운영자 서버 (회원 번호, 네이버·Apple 식별값) | 앱 기능 | 예 | 아니요 |
| 식별자 > **기기 ID** | FCM 토큰(운영자 서버), IDFA(AdMob) | 앱 기능, 타사 광고, 분석 | 예 | **예** |
| 사용 데이터 > **제품 상호작용** | 운영자 서버(화면 접근 기록), AdMob | 앱 기능, 분석, 타사 광고 | 예 | 아니요 |
| 사용 데이터 > **광고 데이터** | AdMob | 타사 광고, 분석 | 아니요 | **예** |
| 위치 > **대략적인 위치** | AdMob (IP 기반) | 타사 광고, 분석 | 아니요 | 아니요 |
| 진단 > **충돌 데이터** | AdMob | 분석 | 아니요 | 아니요 |
| 진단 > **성능 데이터** | AdMob | 분석 | 아니요 | 아니요 |
| 진단 > **기타 진단 데이터** | AdMob | 분석 | 아니요 | 아니요 |
| 기타 데이터 > **기타 데이터 유형** | 운영자 서버 (투자 성향, 앱 설정) | 앱 기능, 제품 맞춤화 | 예 | 아니요 |

입력 순서 팁

1. 위 유형을 모두 체크 → 다음.
2. 유형마다 용도 체크 → "사용자 ID에 연결됩니까?" → "추적 목적으로 사용합니까?" 순으로 표대로 답.
3. "추적에 사용 = 예"가 하나라도 있으면 앱에 ATT 팝업이 있어야 함 → 이미 있음(`NSUserTrackingUsageDescription`, `useAdMob.js`의 `requestTrackingAuthorization`).

판단이 갈리는 부분

- **기기 ID·광고 데이터의 추적 = 예**: AdMob이 ATT 허용 시 IDFA로 다른 회사 앱·웹 데이터와 엮어 광고하므로 Apple 정의상 추적. Google 가이드도 같은 답.
- **IP·User-Agent**: Apple 유형에 IP 항목은 없음. 위치 판단에 쓰지 않으므로 운영자 서버 쪽은 "대략적인 위치"로 넣지 않음.
- **금융 정보는 넣지 않음**: KIS 계좌·API 키 입력란은 `isWorker` 권한 사용자에게만 보임(`UserOption.vue:30`). 일반 사용자에게 이 권한을 주는 일이 생기면 "금융 정보 > 기타 금융 정보"를 추가해야 함.
- **문의 메일**: `mailto:`로 메일 앱을 여는 방식이라 앱이 수집하는 데이터가 아님 → 넣지 않음.

## 5. Apple 로그인 운영 설정

코드는 반영됨. 아래가 끝나야 실제로 동작함.

1. **Apple Developer > Identifiers > `com.chagoklabs.yangbongstore`** 에서 Sign in with Apple 켜기 (Enable as a primary App ID). 앱 entitlements에는 이미 추가함.
2. **Apple Developer > Keys** 에서 Sign in with Apple 키 만들기 → `.p8` 내려받기(한 번만 받을 수 있음), Key ID 기록.
3. **master_infos** 에 `category='APPLE_AUTH'` 로 넣기

| key_type | key_value |
|---|---|
| `APPLE_CLIENT_ID` | `com.chagoklabs.yangbongstore` |
| `APPLE_TEAM_ID` | `454UQ5VBD9` |
| `APPLE_KEY_ID` | 2번 Key ID |
| `APPLE_PRIVATE_KEY` | `.p8` 파일 내용 전체 (줄바꿈 포함, `\n` 으로 넣어도 됨) |

   - `APPLE_CLIENT_ID` 만 있으면 로그인은 됨. 나머지 셋은 계정 삭제 때 Apple 연결 해지용.
   - `APPLE_AUTH` 는 공개 API `/api/oauth/infos/<type>` 허용 목록에 없음 → 키가 밖으로 나가지 않음.
4. 서버 재배포(`web_shared` 변경 → py-yangbong-api, py-secret-api 둘 다 영향), 앱 새 빌드.
5. **가린 이메일로 메일 보내기**: Apple Developer > Services > Sign in with Apple for Email Communication 에 보내는 주소(또는 도메인) 등록. 등록 안 하면 `@privaterelay.appleid.com` 주소로 보낸 메일(공지, 문의 답장)이 전달되지 않음. 로그인·가입 자체와는 무관.
